## 已知调查边界

- 历史 Gitee 迁移逻辑删除根安装基线的行为有代码及历史日志依据。
  本次 2.1.0 → 2.1.1 的直接失败为根 `installer.exe` 缺失，具体删除者尚无证据。
- 历史差分重建 SHA512 不匹配有日志依据；缺少当时完整缓存与传输记录，
  不把某个猜测写成全部失败的共同根因。
- 降低编码输出分辨率不等于降低桌面捕获源分辨率，也不保证提高源刷新率。
- 自动测试、真实本机浏览器/媒体测试、真实 Android 与用户设备体验必须分开报告。

性能结果：同一 240Hz 显示器上，540p VP8（实际源 1000×624、编码约 865×540）
两次对照从约 54–56fps 到 77–78fps；额外实际 1080 高度的一次对照，
采集/编码/解码均 1728×1080，从 46.54fps 到 58.62fps。120fps 仍未达到。
默认只启用已测官方零拷贝转换，不改变码率、分辨率约束、共享调档或媒体生命周期。
AV1 零拷贝功能测试使用实际 AV1/libaom，通过新流解码、非黑画面、停止和复采；
其吞吐、普通模式活动分析、物理显示扫描、广域网、长时发热及其他机器仍未做对照。
详见 [实际测量与原始证据入口](../diagnostics/screen-capture-performance-20261023.md)。

## 统一验收与回滚

冻结后以本文件所列最终产物为准，旧正式包和旧候选包保留。
退出候选客户端/测试服务端即可回到正式应用；不迁移或替换正式数据。
源码可切回回滚分支，不能用强制覆盖方式清除用户后续修改。

1. Windows 解压到新的可写目录，运行 `Server/Start-Server.cmd`，再运行
   `Desktop/Start-Desktop.cmd`。默认仅本机 `http://127.0.0.1:33991`，
   数据和日志位于各自 `acceptance-data`；便携包不检查正式更新或运行安装修复。
   用两个测试账号确认拖拽只改变本人顺序，上传/删除内容仍共同可见。
2. 确认聊天字号按钮已移除；“设置 → 采集设置”只有一个兼容观看开关，
   下次开始共享生效，共享中禁用。手机只统一栏目名，继续原有 VP8 原生共享。
3. 相同动态内容、显示器和档位下观察真实采集/编码/接收数值及画面；
   异常时关闭测试进程，以 `COVE_DISABLE_ZERO_COPY_DESKTOP_CAPTURE=1`
   启动同一候选可回到 Chromium 旧转换路径。不要把档位标签当实际像素或 FPS。
4. Android 测试 APK 由用户自行安装为独立应用，不覆盖正式版、不需要 Metro。
   它严格拒绝接收正式 `com.cove.mobile` 更新包；应用内下载/安装的完整设备流程
   需要后续正式身份的获准候选及递增版本包，不能用放宽身份检查替代。
5. 公网完整差分重建、真实 Windows 安装交接、手机 PackageManager/FileProvider/
   安装来源权限/OEM 安装界面及真实重启行为未完成验收。历史 TLS 失败不算通过，
   未确认的历史缺失基线和 SHA512 根因仍保留为未知。
