# 媒体、恢复与兼容验收矩阵

此矩阵用于同一提交、同一网络条件下复跑。自动结果与人工验收分别记录，
不能把逻辑测试、RTT 或测试运行时间当作真实端到端延迟。

## 可重复的本地检查

本次本地交付的启动入口与实测记录见 [统一验收说明](2026-10-22-improvements.md)。
Windows 下先执行 `./tooling/start-local-test.ps1 -Check` 查看独立目录和端口，
再执行 `./tooling/start-local-test.ps1` 启动测试服务端和桌面客户端；此入口不安装软件。

先构建共享包，再执行对应 CI 门禁或恢复专项：

```powershell
npm run build:packages
node tooling/ci-regression.cjs server
node tooling/ci-regression.cjs desktop
node tooling/ci-regression.cjs mobile
node tooling/verify-media-recovery.cjs --repeat 3 --output runtime/recovery-verification.json
```

专项工具只启动仓库内固定的逻辑、hook 和 loopback 合成测试，不接受服务器
地址，不使用真实麦克风/屏幕。重复次数限制为 1–10，失败后停止；超时或取消
只终止它启动的测试进程树。报告中的 `testDurationMs` 是测试执行耗时。

2026-10-22 的额外双 Chromium 回归已使用真实 WebRTC/SFU、合成麦克风与画面完成
VP8 协商、非黑解码帧、同 session 短暂信令恢复和停止共享后保留语音检查。
结果保存为 `runtime/media-integration-result.json`，每次运行先写入新的 runId 和
未完成状态，清理自有后端后才记录通过。此测试没有使用真实屏幕采集、Android
硬件编码或真实弱网，也没有测量端到端延迟。

桌面打开媒体诊断并导出 JSON；手机打开媒体状态，连续刷新两次后保存 JSON。
离线汇总不读取账号数据，不连接网络，也不输出导出中的 room/socket 标识：

```powershell
node tooling/analyze-media-diagnostics.cjs path/to/export.json > runtime/media-summary.json
```

RTT 指客户端与 SFU 的往返时间；RTP jitter 指包到达时间变化。编码/解码每帧
耗时和码率属于各自采样窗口，不能相加推算采集到显示的延迟。单个手机导出
只有一个窗口，不足以估计长时间分布。端到端延迟需要同画面时钟或外部高速
录像，并记录采集、编码、网络、缓冲、解码和显示条件；工具不会生成该指标。

## 统一用户验收

先用本地测试账号及测试房间，记录提交、客户端/服务端版本、设备、系统、
编解码器、分辨率/帧率、网络和观察时间。不得用现用生产会话作故障注入。

| 场景 | 操作 | 必须观察到的行为 | 自动覆盖 / 人工边界 |
| --- | --- | --- | --- |
| 短信令中断 | 通话和观看时模拟信令 transport close，再恢复同 session | 不重复 produce/consume；静音、观看保持；远控权限撤销且不自动恢复 | loopback + hook；真实网络待验收 |
| 延迟 CONNECT | 连续三轮断开，媒体仍健康，延后客户端 CONNECT | 信令超时不单独破坏健康媒体；媒体失败期限仍独立生效 | 虚拟时间 + 双 transport 失败测试 |
| 服务端状态丢失 | 本地测试服务退出后由测试操作者重新启动 | fresh session 清理旧媒体；不自动重开麦克风或共享 | 客户端 fresh session 测试；双客户端整链路待验收 |
| 主动取消优先 | 恢复/原生路由/初始化等待中离开、切房或取消观看 | 迟到结果不复活旧会话，不清理新会话资源 | 代次、迟到 ACK/路由、Promise 回归 |
| 手机编码回退换流 | 在合成测试中使首 codec 失败并替换 producer | 同一共享 session 有界续看；主动停止后不再消费；旧关闭事件不误停新流 | 乱序 + hook；实际硬件编码失败待验收 |
| 桌面到手机兼容 | 默认模式与显式 VP8 兼容模式分别共享 | 默认策略保留；兼容模式确实使用协商的 VP8；缺能力时报错 | 能力非对称/协商测试；实际机型组合待验收 |
| 多观看者与音频 | 桌面、手机同时观看，切换或停止分享 | 每端仅一份当前流；屏幕音频不串流；停止后均清理 | 合成生命周期；多设备长时待验收 |
| 语音包压力 | 同时上传/后台规范化超过队列容量，取消部分任务 | 并发有界，排满明确失败，取消后释放槽/子进程/临时文件 | 队列 + FFmpeg 合成文件测试 |
| 大列表排序 | 对 500、501、2000 项房间列表排序；另端修改列表后重试 | 完整合法排序成功；失配明确拒绝，无部分写入/跨房修改 | handler + 实际 SQLite |
| Wi-Fi / 蜂窝切换 | Android 真机通话/观看期间切网 | 记录是否同 session 恢复、失败提示与人工重进路径；不误开共享/远控 | 尚需真机验收 |
| 挂起与长通话 | 锁屏/恢复、最小化及至少 30 分钟通话 | 无幽灵会话、持续资源增长或重复播放；导出前后诊断 | 尚需真实客户端与长时验收 |

测试某项时记录“通过/失败/未测”、复现顺序、时间、预期/实际和脱敏诊断。
遇到实际故障先保留这些证据，不通过反复重启现用服务掩盖问题。
