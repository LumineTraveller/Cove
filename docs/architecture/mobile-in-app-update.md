# Android 应用内更新

更新入口仍是 `MobileUpdateProvider` 与登录/房间列表上的版本按钮。聊天服务器选择接口仅为已有调用方保留，不会注册更新源。应用内更新不调用浏览器，也不读取聊天服务器证书例外或登录凭据。

## 分工与任务所有权

- React Native 检查固定 GitHub 清单及编译时配置的 HTTPS 镜像，比较版本、最低客户端要求和镜像元数据。用户点击下载后创建唯一请求 ID，使用原生字节事件显示进度，提供取消与重试；下载成功与安装始终是两个独立步骤。
- `MobileUpdateModule` 校验桥参数中的整数，使用专用下载串行执行器；事件包含请求 ID、清单 hash、实际已接收字节和总大小。下载请求的开始、取消、进度与结果按 ID 关联。主线程只负责打开用户明确请求的系统权限页或安装器，并在启动时再次确认应用仍在前台。
- `MobileApkUpdater` 构造可信源 URL，限制重定向，流式核对大小与 SHA-256，并通过 PackageManager 读取真实 APK 身份。成功缓存和待安装引用都只属于对应下载请求；取消旧请求不能清除新请求的验证状态。安装准备保留原生互斥直到主线程启动或拒绝结束，防止安装准备过程中清理目标缓存。

## 来源与身份边界

GitHub APK 只允许从固定仓库的 Release 路径开始，后续只能跳转到列明的 GitHub HTTPS 资源域名，且仅用 443 端口。镜像和清单均绑定编译配置的 HTTPS 基址；镜像重定向保持同源。清单中即使附带下载 URL，也不会成为原生下载地址。清单与 APK 使用独立的标准 TLS 客户端，限制超时、重定向次数和大小。

完整下载只接受 HTTP 200，拒绝非预期 Content-Range 和压缩编码，不发送 Range、不复用部分内容。流中途失败或取消会删除暂存文件。再次开始时会清理本模块命名规则下的遗留 `.part`；文件未通过校验前不会进入可共享目录。

APK 必须匹配 `com.cove.mobile`、清单 versionName/versionCode/minSdk、严格高于已安装 versionCode，并与当前安装包的非空签名证书集合相同。下载后与每次安装前均检查真实身份；安装前也会重新核对完整大小及 SHA-256。未来签名轮换需要独立设计迁移，不能信任清单提供的新证书。

FileProvider 只暴露私有 `updates/verified/`，不包含 `updates/staging/`、锁文件或其他应用文件。URI 仅来自已验证文件引用，只授予读取权限，最终确认由系统安装器处理。Android 安装来源权限只能由用户在系统设置中选择；拒绝或返回后不会自动再次启动。

## 中断、缓存与验收

后台/Activity 暂停会取消正在下载的请求；React Native 也会立即废弃对应回调。超时和用户取消后可手动重试，旧任务的晚到事件不会改变新任务。进程重启后不恢复内存中的安装资格；下一次从可信清单选择同一包后，可重新核验已完成缓存再复用。存储预检查预留包大小及 8 MB，写入时空间耗尽也给出明确错误。系统安装自身所需的额外空间由 Android 再次检查。

`com.cove.mobile.refactor` 验收包不能安装正式候选；该边界在原生下载入口明确拒绝。正式版本、签名策略和线上清单保持原状。自动化覆盖 React 状态、过期回调、HTTP 故障、校验、请求取消、遗留暂存清理和身份契约。JVM 测试并非设备上的 PackageManager/FileProvider/系统安装器验收；权限拒绝、安装取消、OEM 差异及真实进程重启仍需在后续获准的独立测试设备上验证。
