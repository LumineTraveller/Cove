# 语音包处理资源边界

HTTP 上传、启动时旧语音包规范化和直接响度检测共用一个进程级 FIFO 队列。
一个名额覆盖完整的测量、短片段 RMS 回退和 MP3 编码，不能在阶段之间绕开限制。

| 边界 | 默认限制 | 反馈 |
| --- | --- | --- |
| 同时运行的完整任务 | 2 | 其余进入 FIFO |
| 等待任务 | 16 | 满时 HTTP 503 / `SOUNDPACK_QUEUE_FULL` |
| 最长排队时间 | 30 秒 | HTTP 503 / `SOUNDPACK_QUEUE_TIMEOUT` |
| 单任务执行总预算 | 90 秒 | HTTP 408 / `SOUNDPACK_PROCESSING_TIMEOUT` |
| 每个 FFmpeg 子进程 | 30 秒 | 同上 |
| FFmpeg 错误/测量报告 | 256 KiB | 超出则终止，不无限积累报告 |

这些是资源保护上限，不是性能测量值。8 MiB 上传大小、原始文件保留、响度/峰值
目标和 MP3 参数保持原行为。每个 FFmpeg 隐藏启动、没有 shell/stdin，解码、滤镜
和输出编码线程设为 1，避免单次处理自行扩张线程数。没有新增依赖。

`soundpackWorkQueue.ts` 管理等待、执行预算和取消；`soundpackFfmpeg.ts` 只管理
子进程。上传断连、请求中止或本地服务器生命周期停止通过 AbortSignal 取消。
排队任务立即移除；正在运行的任务发送终止信号，必须等子进程 `close` 后才
拒绝 Promise、释放队列名额。这样调用方不会在 FFmpeg 仍写文件时删临时文件。

HTTP 路由和旧包规范化拥有文件与数据库提交：失败/取消删除未提交文件，成功时
先重新检查当前房间/账号权限，再原子替换播放文件、写数据库并通知。取消不会
写入新记录；旧包规范化取消保留原文件。忙碌响应带 `Retry-After: 2`，客户端
显示错误后由用户重试，没有新增自动重复上传。

可重复测试覆盖：队列容量/FIFO、等待与执行独立预算、排队取消、运行取消不提前
释放名额、重复取消、报告溢出、子进程错误/退出、上传与服务器生命周期取消、
临时文件清理和成功文件保留。既有合成正弦/短片段/静音规范化与房间隔离集成
继续通过；另用真实 FFmpeg 的合成实时读取验证取消后子进程确已关闭。
